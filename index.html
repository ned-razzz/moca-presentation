Mobility Catering Service

MoCa

이동형 로봇 케이터링 스낵바 서비스. 점주 1명과 로봇이 주문, 제조, 서빙, 모객까지 함께 수행하는 현장 맞춤형 무인 카페 솔루션입니다.

01 / 주제 선정 이유

로봇 매장은 자동화만으로는 충분하지 않습니다.

기존 로봇 매장의 한계

  • 공간마다 필요한 매장 형태가 다르지만 인프라는 고정적입니다.
  • 인건비와 구축 비용이 높아 행사장·팝업 환경에 맞추기 어렵습니다.
  • 로봇이 반복 작업만 수행하면 고객과의 상호작용이 부족합니다.

MoCa의 방향

어디든 이동하고, 행사 테마에 맞게 바뀌며, 최소 인력으로 운영되는 이동형 스낵바를 목표로 했습니다.

02 / 프로젝트 개요

사람은 운영을 관리하고, 로봇은 반복 업무를 수행합니다.

1점주 1명이 주문·로봇·매장 상태를 통합 관리
2뚜비와 도비가 제조·서빙 업무를 분담
4행사장에 맞춰 맵·메뉴·로봇 위치 구성
∞테마와 현장에 맞게 바뀌는 케이터링 서비스

구성 요소

제조 로봇 뚜비, 서빙·모객 로봇 도비, 관리자 시스템, 맞춤형 맵 편집 기능을 하나의 운영 흐름으로 연결했습니다.

03 / 주요 서비스 흐름

초기 세팅부터 서빙까지 하나의 작업 흐름으로 이어집니다.

01

초기 세팅

행사장 맵, 메뉴, 로봇 위치, 픽업존과 테이블을 설정합니다.

02

주문·결제

고객이 GUI, 자연어, 음성 기반으로 메뉴를 선택하고 결제합니다.

03

제조

뚜비가 레시피와 비전 인식 결과를 기반으로 음료와 스낵을 제조합니다.

04

서빙

도비가 픽업존에서 상품을 싣고 테이블까지 운반한 뒤 대기 장소로 복귀합니다.

04 / 주문

고객은 상황에 맞는 방식으로 주문하고, 시스템은 제조와 서빙을 시작합니다.

주문 방식

  • GUI 주문으로 메뉴를 직접 선택합니다.
  • 자연어 주문으로 메뉴 탐색과 확인을 대화형으로 진행합니다.
  • 음성 주문은 STT, LLM, TTS 흐름으로 확장합니다.

결제 방식

카드 결제와 앱 Pay 흐름을 기준으로 주문 완료 후 제조 큐에 작업을 전달합니다.

05 / 제조

뚜비는 비전으로 보고, 물체를 파악하고, MoveIt 기반 동작을 수행합니다.

비전 기반 제어 흐름

  • Depth 카메라로 물체의 위치와 자세를 획득합니다.
  • PCA 알고리즘으로 주축을 파악해 파지 진입 방향을 결정합니다.
  • MoveIt planning과 Cartesian path를 조합해 제조 task를 실행합니다.

시뮬레이션에서 실물로

Gazebo 월드를 구축하고 검증한 뒤, 시뮬레이션과 실물 로봇의 간극을 보정해 전이했습니다.

06 / 서빙

도비는 픽업, 운반, 제공, 복귀를 자율 서빙 흐름으로 연결합니다.

ACT Policy 기반 서빙

하드웨어 리소스와 실시간성을 고려해 VLA보다 가벼운 ACT Policy를 채택하고, 픽업대·테이블 환경 변화에 대응하도록 데이터를 수집했습니다.

데이터 엔지니어링

  • 형광등 플리커와 조명 변화를 데이터 증강으로 완화했습니다.
  • 다양한 위치와 각도에서 데이터를 수집해 객체 위치 변화에 대응했습니다.
  • 상호작용에 따라 픽업과 제공 행동을 분리해 학습했습니다.

07 / 모객

유휴 시간의 도비는 고객을 탐지하고, 접근하고, 친밀도를 높입니다.

모객 진행 흐름

  • 고객 군집 또는 호출 대상자를 탐지합니다.
  • 안전거리와 방향을 유지하며 접근합니다.
  • 아바타, 음성, 미니게임으로 Ice Break를 수행합니다.
  • 호응도와 친밀도에 따라 메뉴를 제안하고 카운터로 안내합니다.
감정 인식 미니게임 호응도 분석 안전 거리

08 / Doby 기술 구조

두뇌, 눈, 손이 공통 감정 인지 파이프라인을 공유합니다.

두뇌

doby_controller

Nav2, BehaviorTree, 5-state FSM, persona router를 통해 주행·전략·대화·표정을 결정합니다.

눈

scout_reactor

PTZ 카메라와 아두이노 2축 서보로 손든 고객 호출과 시선을 추적합니다.

손

omx_reactor

OpenManipulator-X 팔로 환영, 응원, 하이파이브 등 표현 모션을 수행합니다.

09 / 5-state + 6-stage

작업 전환은 FSM, 모객 내부 행동은 BehaviorTree로 분리했습니다.

5-state FSM

  • idle, serving, patrol, guiding, engaging 상태를 관리합니다.
  • 더 급한 작업이 들어오면 우선순위 기반으로 선점합니다.
  • ROS 런치 스택의 생사와 운영 모드를 제어합니다.

6-stage Funnel

  • IDLE, APPROACH, ICEBREAK, MINIGAME, OFFER, LEAD-IN 순서로 진행합니다.
  • rapport 게이팅으로 단계 진입을 결정합니다.
  • 분노·불쾌 감지 시 어느 단계에서든 즉시 중단합니다.

10 / 감정 인식

픽셀을 표정 근육, 감정 점수, V·A 좌표로 단계적으로 추상화합니다.

공통 파이프라인

  • MediaPipe로 얼굴점 468개와 blendshape 52개를 추출합니다.
  • 규칙 기반 가중합으로 7개 감정 점수를 계산합니다.
  • Russell Valence·Arousal 좌표로 감정 추이를 읽습니다.
  • EMA와 Hysteresis로 떨림을 줄이고 중단 조건을 안정화합니다.

11 / 안전

사람 옆 로봇을 위해 물리, 운영, 사회적 안전을 겹쳐 설계했습니다.

Hard Safety

LiDAR 거리와 배터리 상태를 기준으로 감속·정지를 수행합니다.

Pause Gate

운영 중 감시된 정지 상태를 만들고, 조건 회복 후 자동 재개합니다.

Social Monitor

분노·불쾌 감정 영역이 감지되면 모객을 중단하고 사과·후퇴합니다.

12 / 관리

점주는 주문, 로봇 상태, 맵, 로그를 하나의 관리자 시스템에서 봅니다.

관리 기능

  • 행사장 환경에 맞춘 맵 편집과 테이블 배치
  • 로봇·기기 상태 모니터링과 운영 모드 제어
  • 주문·제조·서빙 진행 상태 확인
  • 이벤트 로그 조회와 개발용 필터링 도구

13 / 설계

하드웨어, 소프트웨어, 데이터, GUI를 분리해 운영 흐름을 구성했습니다.

14 / 협업

스프린트 단위 개발과 명확한 브랜치 전략으로 통합 안정성을 유지했습니다.

애자일 기반 스크럼

  • Sprint #1부터 #4까지 반복 개발하며 기능을 점진적으로 통합했습니다.
  • 각 모듈의 진행 상황과 이슈를 공유하고 다음 작업을 재조정했습니다.
  • 실물 로봇 검증 결과를 다음 스프린트의 요구사항에 반영했습니다.

브랜치와 스타일

  • feat/* → dev → main 흐름으로 기능 개발과 배포를 분리했습니다.
  • C++은 Google Style Guide, Python은 PEP 8을 기준으로 관리했습니다.
  • 정상 동작이 보장된 상태만 dev와 main으로 통합했습니다.
