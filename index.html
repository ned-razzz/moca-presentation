02 / 기획

왜 이동형 로봇 케이터링 서비스인가?

주제 선정 이유

  • 행사장, 팝업스토어, 테마 공간마다 필요한 매장 형태가 다름
  • 기존 방식은 인력 운영과 인프라 구축 비용 부담이 큼
  • 로봇과 사람이 협업하면 최소 인력으로 운영 가능
  • 메뉴와 공간 변화에 유연하게 대응하는 서비스가 필요함
어디든 이동하고, 공간에 맞게 바뀌며, 최소 인력으로 운영되는 서비스

03 / 기획

MOCA: 이동형 로봇 케이터링 서비스

프로젝트 개요

MOCA는 점주 1명과 로봇이 협업하여 주문, 제조, 서빙, 모객까지 수행하는 이동형 로봇 케이터링 플랫폼이다.

서비스 구성

  • 제조 로봇 뚜비: 주문 메뉴 제조
  • 서빙 로봇 도비: 픽업, 테이블 서빙, 모객
  • 관리자 시스템: 주문·로봇·매장 상태 통합 관리
  • 맞춤형 매장 맵: 행사장 환경에 맞게 구성
사람은 운영을 관리하고, 로봇은 반복 업무를 수행한다.

04 / 기획

MOCA 서비스를 구현하기 위한 핵심 요건

맞춤형 매장 구성 다양한 행사장에 맞게 맵과 서비스 환경을 구성
자동 제조·서빙 주문 후 뚜비와 도비가 유기적으로 작업 수행
안전·인터랙션 사람과 함께 움직이는 로봇의 안전성과 친밀감 확보
통합 관리 점주 1명이 전체 주문, 로봇, 매장 상태를 관리
이동성, 자동화, 안전성, 관리성을 모두 만족해야 한다.

05 / 기획

초기 세팅부터 서빙까지

01

초기 세팅

매장 맵, 메뉴, 로봇 위치를 설정한다.

02

주문·결제

고객이 메뉴를 선택하고 결제를 완료한다.

03

제조

제조 로봇 뚜비가 주문 메뉴를 제조한다.

04

서빙

서빙 로봇 도비가 픽업 후 고객 테이블까지 전달한다.

주문이 들어오면 제조와 서빙이 자동으로 연결된다.

06 / 기획

유휴 시간의 도비 활용

모객 서비스

  • 서빙 대기 시간에 도비가 홀을 순회
  • 고객에게 메뉴, 이벤트, 서비스 안내 제공
  • 게임이나 간단한 인터랙션으로 관심 유도
  • 고객 반응이 좋지 않으면 반복 접근하지 않음
  • 안전거리와 주행 규칙을 기반으로 이동
도비는 단순 서빙 로봇을 넘어 고객을 끌어들이는 서비스 로봇이다.

07 / 기획

점주 1명이 전체 매장을 관리하는 구조

통합 관리

  • 주문 현황 확인
  • 제조 진행 상태 모니터링
  • 서빙 로봇 위치 및 상태 확인
  • 매장 운영 모드 제어
  • 이상 상황 발생 시 관리자 개입
최소 인력 운영을 위해 모든 상태는 한눈에 관리되어야 한다.

08 / 기능 및 기술

주문: 자연어 기반 주문·결제 흐름

대표 주문 방식

  • 메뉴 선택 GUI와 자연어 음성 입력을 함께 제공
  • QWEN3-ASR로 사용자 발화를 텍스트화하고 Audio LLM으로 주문 의도 파악
  • 메뉴 확인 후 카드 결제와 앱 Pay 결제 흐름으로 연결
고객은 말로 주문하고, 시스템은 메뉴 확인과 결제까지 하나의 흐름으로 처리한다.

09 / 기능 및 기술

제조: 비전 기반 조작과 시뮬레이션 전이

제조 흐름

  • 주문 확인 후 레시피에 따라 핫도그와 음료 제조 태스크 수행
  • Depth 카메라로 물체 위치를 획득하고 PCA로 주축을 파악해 파지 진입 방향 결정
  • MoveIt Planning과 Cartesian Path를 조합해 케이스 집기, 빵·소시지 배치, 픽업존 배치 실행
  • Gazebo 월드 검증 후 실물 로봇과의 간극을 보정해 전이
보고, 파악하고, 행동하는 제조 로봇 뚜비의 조작 파이프라인

10 / 기능 및 기술

서빙: 픽업·운반·제공을 연결하는 자율주행

서빙 흐름

  • 주문 확인 후 픽업존에서 상품을 수령하고 고객 테이블까지 운반
  • 샌드위치, 음료, 스낵 등 상품 유형별 픽업·제공 동작 분리
  • ACT Policy를 채택해 하드웨어 리소스와 실시간 제어 안정성을 우선 확보
  • 위치·각도 다변화 데이터와 밝기 변화 증강으로 실제 환경 변화 대응
제조 완료 시점부터 고객 테이블 제공까지 도비가 서비스 흐름을 이어받는다.

11 / 기능 및 기술

모객: 감정 인식 기반 고객 인터랙션

도비 모객 구조

  • 점주가 모드 제어 웹 인터페이스로 모객 모드를 수동 실행
  • 사람 탐지 후 접근, 아이스브레이크, 미니게임, 메뉴 제안, 카운터 안내 순서로 진행
  • doby_controller, scout_reactor, omx_reactor가 두뇌·눈·손 역할을 분담
  • MediaPipe 얼굴 특징과 Valence·Arousal 좌표로 호응도와 중단 조건 판단
  • 물리 안전, 운영 정지, 사회적 후퇴를 분리한 3계층 안전 구조 적용
도비는 고객 반응을 읽고 억지로 붙잡지 않는 모객 퍼널로 행동한다.

12 / 기능 및 기술

관리: 맵·주문·로봇 상태 통합 운영

관리 기능

  • 행사장 환경에 맞춰 서비스 맵을 편집하고 테이블·픽업존·로봇 위치를 구성
  • 주문, 제조, 서빙, 로봇 상태를 관리자 화면에서 실시간 확인
  • 운영 모드 제어와 이상 상황 개입으로 점주 1명의 운영 부담 축소
  • 이벤트 로그와 개발용 필터링 로그로 로봇·기기·서버 상태 추적
이동형 매장은 현장마다 달라지므로 맵과 운영 상태를 한 화면에서 다뤄야 한다.

14 / 결론

추후 계획

서비스 고도화 방향

  • 행사장별 맵 템플릿과 초기 세팅 절차를 단축해 이동형 운영성을 강화
  • 제조·서빙 데이터셋을 확장해 메뉴와 환경 변화에 대한 강건성 확보
